# DA3 ggml port — M8 (LocalAI backend) Implementation Plan

> REQUIRED SUB-SKILL: superpowers:subagent-driven-development.

**Goal:** Deploy the verified DA3 port as a LocalAI backend: a **static-linked shared library** (no external libggml), a **purego Go binding** that loads the model and runs depth/pose/reconstruct via the C-API, a **gRPC Backend service** wrapping it, and packaging (Makefile pinned to a commit SHA, Dockerfile, gallery yaml, README). The C-API (`da_capi_load/free/info_json/depth_pose_path/pose_path/depth_pose_multi/last_error/abi_version`) already exists.

**Critical requirement (porting skill L0):** the `.so` must STATICALLY link ggml (`-DBUILD_SHARED_LIBS=OFF -DCMAKE_POSITION_INDEPENDENT_CODE=ON`) so `ldd libdepthanything.so` shows **no libggml** — else the backend dies at runtime with "cannot open libggml.so". The CMake already sets `BUILD_SHARED_LIBS OFF` + PIC and `DA_SHARED` builds the lib SHARED; verify the result is self-contained.

LocalAI Backend gRPC service (from `~/_git/LocalAI/backend/backend.proto`): methods incl. `Health`, `LoadModel(ModelOptions)→Result`, `Predict(PredictOptions)→Reply`, `GenerateImage(GenerateImageRequest)→Result`, `Status`. Depth has no native OpenAI endpoint, so expose depth via **GenerateImage** (input image path in the request → write the depth-map PNG to the requested dst) and/or `Predict` returning JSON (depth stats + pose). Model loads via `LoadModel`.

## Notes
- The C side is NOT reentrant (shared ggml gallocr per Backend) — the Go gRPC handler must serialize inference (single mutex), matching LocalAI's `base.SingleThread`.
- Static-link is the make-or-break: verify `ldd` shows no libggml AND the Go purego load succeeds at runtime.
- Full LocalAI registration (index.yaml, backend matrix, gallery in the LocalAI monorepo) is documented in README as the integration steps; the backend code + packaging live here.
- Pin the Makefile to a depth-anything.cpp commit SHA and tag it (so a squash upstream can't orphan it), per the porting skill.
